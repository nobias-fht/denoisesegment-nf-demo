# nobias-fht/denoisesegment: Output

## Introduction

This document describes the output produced by the pipeline.

The directories listed below will be created in the results directory after the pipeline has finished. All paths are relative to the top-level results directory. Exact CAREamics checkpoint and prediction filenames are determined by CAREamics and the input filenames.

## Pipeline overview

The pipeline is built using [Nextflow](https://www.nextflow.io/) and processes data using the following steps:

- [CAREamics](#careamics) - N2V configuration, training artefacts, and denoised images
- [Cellpose](#cellpose) - Process-level Cellpose mask output
- [Segmentations](#segmentations) - Final labelled segmentation masks
- [Pipeline information](#pipeline-information) - Software versions and reports generated during workflow execution

### CAREamics

<details markdown="1">
<summary>Output files</summary>

- `careamics/`
  - `careamics.yaml`: generated N2V training configuration.
  - `**/*.ckpt`: trained model checkpoints, including the checkpoint selected for prediction.
  - `**/checkpoint_record.json`: checkpoint metadata identifying the model selected for prediction.
  - `**/metrics.csv`: training and validation metrics logged by CAREamics.
  - Denoised TIFF image(s) produced from the input data.

</details>

CAREamics creates the N2V configuration, trains a self-supervised denoising model on `--input`, and applies the selected checkpoint to the same input. If `--careamics_val_data` is supplied, those images are used as the separate validation data during training. The denoised TIFF images are the inputs to Cellpose.

### Cellpose

<details markdown="1">
<summary>Output files</summary>

- `cellpose/`
  - `**/*masks.tif`: labelled mask TIFF emitted by the Cellpose process for each denoised image.

</details>

Cellpose runs independently for every TIFF emitted by CAREamics. The pipeline uses the default Cellpose model and passes optional channel-axis, Z-axis, and 3D settings when their corresponding pipeline parameters are supplied.

### Segmentations

<details markdown="1">
<summary>Output files</summary>

- `segmentations/`
  - `*masks.tif`: final labelled instance-segmentation mask for each denoised input image.

</details>

This is the primary pipeline output. Pixel values in each mask identify segmented instances; background pixels have the background label used by Cellpose. These files are also present in the process-level `cellpose/` output described above.

### Pipeline information

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/`
  - Reports generated by Nextflow: timestamped `execution_report_*.html`, `execution_timeline_*.html`, `execution_trace_*.txt`, and `pipeline_dag_*.html` files.
  - Collated software versions: `denoisesegment_software_versions.yml`.
  - Parameters used by the pipeline run: `params.json`.

</details>

[Nextflow](https://docs.seqera.io/platform-cloud/reports/overview) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
